# AI_USAGE.md
## Record of AI Tool Usage & Corrections

In accordance with the evaluation requirements of Onnorokom Projukti Limited, this document provides an honest and comprehensive account of AI tool assistance, areas of contribution, errors encountered, and human verification performed during this project.

---

### 1. AI Tools Utilized
- **OpenAI ChatGPT (GPT-4o):** Used in the initial phase for analyzing the Bengali project specification, understanding domain nuances (e.g., Bangladeshi 17-digit Birth Registration Number structure, first-come first-served admission vs lottery dynamics), identifying potential edge cases, and brainstorming concurrency patterns.
- **Google Antigravity Coding Assistant (Gemini):** Used as the primary pair-programming copilot for architectural scaffolding, backend & frontend implementation, integration testing, Docker orchestration, and documentation formatting.

### 2. Areas of Assistance
1. **Domain Understanding & Requirement Analysis (ChatGPT):**
   - Dissecting the original assignment specification (`Asst_Software_Engineer_Project_Assignment.pdf`) to ensure complete comprehension of business rules, state transitions, and edge cases.
   - Conceptualizing the seat hold lifecycle (10-minute countdown, automatic expiration, idempotent payment confirmation).
2. **Requirements Extraction & Traceability Matrix (Antigravity):**
   - Translating business rules into a 32-item traceability matrix and auditing API contracts.
3. **Architecture & Solution Scaffolding (Antigravity):**
   - Scaffolding the .NET 8 clean modular architecture (`SchoolAdmission.sln` with Domain, Application, Infrastructure, Api, and Test projects).
   - Scaffolding the React 19 + TypeScript + Vite + Tailwind CSS v4 frontend.
4. **Pessimistic Concurrency Strategy (Antigravity):**
   - Formulating PostgreSQL row-level locking (`SELECT FOR UPDATE`) within database transactions to ensure `HeldSeats + ConfirmedSeats <= TotalSeats` under high simultaneous traffic.
   - Designing transaction-scoped advisory locks (`pg_advisory_xact_lock`) for cross-class same-student race condition prevention.
5. **Automated Testing Suite (Antigravity):**
   - Authoring unit tests for domain invariants, validation rules, and idempotency.
   - Authoring integration tests including the mandatory 100-request high-concurrency seat allocation test.
6. **Docker & Container Orchestration (Antigravity):**
   - Multi-stage Dockerfiles for .NET 8 ASP.NET Core API and React/Nginx SPA.
   - Root `docker-compose.yml` with health checks, persistent volumes, and environment wiring.

### 3. Meaningful Errors, Hallucinations & Critical Corrections

| Issue / Error Encountered | Cause | Detection Method | Resolution Applied |
|---|---|---|---|
| **Thread Pool Starvation in Concurrency Test** | AI initially used a synchronous `Barrier(100)` inside `Task.Run` to synchronize 100 simultaneous HTTP requests. | Test execution hung and timed out because 12 worker threads blocked on the barrier, preventing the remaining 88 tasks from being scheduled. | Replaced the blocking `Barrier` with a non-blocking asynchronous `TaskCompletionSource<bool>`. All 100 tasks await the token without consuming threads, firing simultaneously when signaled. |
| **xUnit Parallel Database Race Collisions** | AI did not disable parallelization across test classes sharing the PostgreSQL database. | Integration tests failed intermittently because `ResetDatabaseAsync` truncated tables while another test class was executing queries. | Configured `[assembly: CollectionBehavior(DisableTestParallelization = true)]` and grouped test classes under `[Collection("IntegrationTests")]` to guarantee strict sequential execution. |
| **Docker Desktop GPG Credential Store Error** | `~/.docker/config.json` contained `"credsStore": "desktop"`, which attempted to launch an interactive GUI PIN entry dialog in a headless terminal. | `docker pull` failed with `gpg: decryption failed: Operation cancelled`. | Inspected `~/.docker/config.json`, removed the desktop credsStore override, and configured standard authentication. |
| **TypeScript Strict Compilation Errors** | Unused imports and variables (`useEffect`, `CheckCircle`, Lucide props) and missing Vite environment types. | `npm run build` failed during strict `tsc -b` type checking. | Added `"types": ["vite/client"]` to `tsconfig.json` and cleaned up all unused imports across components. |
| **Host Port 5432 Collision** | Host machine had a preexisting system PostgreSQL service listening on port 5432. | `docker run` failed with `address already in use` when binding `5432:5432`. | Configured `docker-compose.yml` with `${DB_PORT:-5434}:5432` and internal container networking `db:5432`, preventing host port collision while keeping internal communication standard. |
| **Cross-Class Simultaneous Student Race Condition** | When simultaneous requests for the SAME student targeted DIFFERENT classes, class-level `SELECT FOR UPDATE` locks did not serialize requests across different classes, allowing two holds to be created for one student. | Authoring the cross-class concurrency test `SameStudent_SimultaneousHoldRequestsAcrossDifferentClasses_ExactlyOneSucceeds` revealed `[Created, Created]` instead of `[Created, Conflict]`. | Implemented PostgreSQL transaction-scoped advisory locks on the student ID: `SELECT pg_advisory_xact_lock(hashtext(@studentId))`, guaranteeing cross-class serialization at the database engine level. |
| **PostgreSQL Connection Pool Burst Exhaustion** | 100 simultaneous concurrent HTTP requests in integration testing exhausted PostgreSQL's default 100-connection client limit. | Concurrency test failed with `Npgsql.PostgresException: 53300: sorry, too many clients already`. | Increased PostgreSQL `max_connections` to 300 in `docker-compose.yml` and configured client pool connection settings in test harness. |
| **Missing Student Switching System & Hardcoded Default ID** | AI initially pre-filled a hardcoded Student ID (`20152691234567890`) on initial load and did **not** build any workflow to switch applicants cleanly or purge stale client caches between different students sharing one browser. | **Human Manual Testing:** Testing the live UI manually revealed there was no dedicated student switching system and no fresh anonymous entry state. | Directed the implementation of an anonymous landing state plus a dedicated **Switch Student** system: confirmation modal (`SwitchStudentModal`), automated `queryClient.clear()` cache purge, and verified PostgreSQL hold persistence when switching between multiple students on the same workstation. |
| **Top-of-Page BRN Input Deviation & Demo Button Design** | AI initially moved the BRN input solely into a landing card modal and auto-triggered demo sessions, diverging from: *"Page-এর উপরে একটা ঘরে শিক্ষার্থীর জন্ম নিবন্ধন নম্বর লেখা যাবে।"* | Manual compliance review against the Bengali specification. | Restored `#top-brn-input` permanently in the header, removed automatic demo login, and later introduced an explicit non-auto-saving **Demo ID** quick-fill helper that only populates the box so evaluators still confirm manually via **Submit ID**. |
| **Premature Auto-Save & Unprotected Post-Submit Input** | Typing the 17th digit automatically saved and activated the student identity without explicit confirmation, and `#top-brn-input` remained editable after activation, risking accidental edits without clearing session cache. | Hands-on manual UI testing in Chrome while typing/editing 17-digit BRNs. | Replaced implicit 17-digit auto-save with a dedicated **Submit ID** button (`Enter` or click), added input locking (`disabled` with `Lock` icon + `Active` badge) once submitted so the ID cannot be altered until **Switch Student** is clicked, and expanded Vitest assertions to 6 workflow tests. |
| **Tablet (`768px`) Navbar Cutoff & Narrow (`260px`) Layout Overflow** | On `768px` tablet viewports the navbar overflowed horizontally off the right edge (`Admin` link clipped), Admin table headers broke mid-word (`HEL/D`, `CONFIRM/ED`), and stacked toasts/filter chips crowded `260px` screens. | Multi-viewport manual & Chrome DevTools live audit (`260px`, `320px`, `375px`, `768px`, `1280px`). | Reworked `Navbar` wrapping breakpoints, enabled CSS `@container` stacked card tables below `680px`, added `min-w-0` flex shrinking, coarse-pointer `44px` touch targets, `sm:w-52` unclipped placeholder width, and a 2-toast display cap — achieving **0 overflows** from `260px` to desktop. |
| **Swagger UI OpenAPI 3.0.4 Version Rejection** | Transitive upgrade via `Microsoft.AspNetCore.OpenApi` brought in `Microsoft.OpenApi 1.6.31`, causing the JSON endpoint to emit `"openapi": "3.0.4"`. Swashbuckle 6.6.2's bundled Swagger UI regex `^3\.0\.([0123])` only accepted patch versions 0 through 3, rendering *"Unable to render this definition. The provided definition does not specify a valid version field."* | Manual live browser inspection of `http://localhost:8080/swagger` and bundle regex analysis. | Replaced `Microsoft.AspNetCore.OpenApi` with explicit `<PackageReference Include="Microsoft.OpenApi" Version="1.6.14" />` (the exact version Swashbuckle targets), ensuring `"openapi": "3.0.1"` is emitted. |
| **Roslyn Performance & Allocation Warnings (CA1861 & CA1869)** | Passing inline constant arrays to CORS options allocated heap memory repeatedly (CA1861), and instantiating `new JsonSerializerOptions` on every handled exception discarded reflection/converter caches (CA1869). | Manual IDE & Roslyn static analyzer inspection of `Program.cs` and `ExceptionHandlingMiddleware.cs`. | Extracted `DefaultAllowedOrigins` to a `static readonly string[]` field, and cached `JsonSerializerOptions` in a `private static readonly` instance in `ExceptionHandlingMiddleware`. |
| **C# 12 Primary Constructors & Source-Generated Regex** | Controllers, middleware, and domain exceptions used repetitive boilerplate constructor injection, and `StudentIdValidator` compiled regex at runtime via `RegexOptions.Compiled`. | Manual C# 12 & analyzer audit against .NET 8 best practices. | Converted controllers and middleware to C# 12 primary constructors, simplified domain exceptions, upgraded `ClassEntity.Holds` to collection expression `[]`, and implemented `[GeneratedRegex]` compile-time source generation in `StudentIdValidator`. |
| **Missing Local-Dev Onboarding Separation** | Only root Docker `.env.example` existed, making standalone local `.NET` + `Vite` development harder to configure. | Manual review of local developer onboarding steps without full Docker. | Added dedicated `backend/.env.example` and `frontend/.env.example` templates and documented step-by-step hybrid/local startup commands in `README.md`. |
| **Frontend Docker Base Image Vulnerability Alerts (`node:22-alpine` & `nginx:alpine`)** | Floating older Node 22 LTS and full `nginx:alpine` images included unrequested Nginx modules (`njs`, `xslt`, `image-filter`, `geoip`) and flagged Critical/High CVEs in Docker DX/Scout. | Manual IDE Docker DX diagnostic review on `frontend/Dockerfile`. | Upgraded build stage to current Active LTS `node:26-alpine`, switched runtime stage to `nginx:1.31.8-alpine-slim` with `RUN apk upgrade --no-cache`, and added BuildKit cache mounts + `scripts/ensure-deps.mjs` (reducing runtime image size from `94.4MB` to `21.8MB`). |
| **Missing Global Error/404/Loading Views & Strict `any` / IDE TS Resolution** | Unmatched routes redirected silently to `/`, initial/failed queries showed misleading empty states (`No classes created yet`), several error handlers used `err: any`, and monorepo root lacked `.vscode/settings.json` `typescript.tsdk`. | Manual frontend UX audit and IDE TypeScript inspection (`StudentPortalPage.tsx` implicit `any` / `@tanstack/react-query` TS server diagnostics). | Implemented `GlobalErrorBoundary`, `ErrorPage` (`errorElement`), `NotFoundPage` (`404`), semantic `<progress>` `LoadingState` & lazy `PageLoader`, centralized `getErrorMessage(unknown)` helper, explicit TanStack Query generics (`0` `any` types across `frontend/src`), `.vscode/settings.json` `typescript.tsdk`, and 7 new tests in `GlobalFeedbackStates.test.tsx`. |

### 5. Human Manual Testing, Feature Directives & Hands-On QA Log
While ChatGPT and Antigravity accelerated requirement parsing and scaffolding, the final UX, stability, and correctness were shaped directly by continuous **human manual testing, code review, and feature directives**:
1. **Manual Requirement Analysis (Pre-Code):** Used ChatGPT to dissect the Bengali specification, domain rules (17-digit Bangladeshi BRN leading-zero preservation, FCFS admission vs. lottery, passwordless `X-Student-Id` flow), and concurrency invariants before writing code.
2. **Switch Student System & Multi-Applicant Isolation (Human-Initiated Feature):** Noticeably, the initial AI scaffold lacked any dedicated **Switch Student** workflow and pre-seeded a hardcoded BRN. After testing the running portal manually, I directed building a full **Switch Student** modal (`SwitchStudentModal`), clearing `localStorage` and TanStack Query cache (`queryClient.clear()`), and proving that previous applicants' server holds remain untouched in PostgreSQL when switching back and forth.
3. **Strict Specification Fidelity & Form Safety Controls (Human-Driven):**
   - Caught an AI deviation that relocated the top BRN box and ensured `#top-brn-input` stayed anchored at the top of the page.
   - Tested typing BRNs manually and directed replacing instant 17th-digit auto-save with an explicit **Submit ID** button, **locking (`disabled`)** `#top-brn-input` until **Switch Student** is clicked (preventing accidental mid-session edits), and adding a non-auto-saving **Demo ID** quick-fill helper for evaluators.
4. **Manual Swagger UI & API Debugging (`OpenAPI 3.0.4` Fix):** Opened `/swagger` manually in Chrome, caught the *"Unable to render this definition"* failure caused by transitive `Microsoft.OpenApi 1.6.31` emitting `"openapi": "3.0.4"`, and pinned `1.6.14` (`3.0.1`).
5. **IDE / Roslyn Static Analysis & Modernization:** Reviewed Visual Studio / Roslyn diagnostics manually and resolved `CA1861`, `CA1869`, `[GeneratedRegex]`, collection expressions `[]`, and C# 12 primary constructors across controllers, middleware, and domain exceptions.
6. **Live Google Chrome Testing & `260px`+ Cross-Device Responsiveness:** Tested every Student and Admin workflow live in Chrome (`http://localhost:3000`) down to **`260px` mobile width** and **`768px` tablet width**, directing fixes for `768px` navbar right-edge overflow, `@container` stacked table cards, input placeholder width, and refreshed all 9 screenshots in `e2e_evidence/`.
7. **Developer Onboarding & Local Environment Separation:** Requested separate `frontend/.env.example` and `backend/.env.example` templates plus full non-Docker local run commands in `README.md`.
8. **Frontend Container Security, Global UX States & Strict TypeScript Inspection (Human-Directed):** Inspected IDE Docker DX vulnerability warnings on `frontend/Dockerfile` (`node:22-alpine`, `nginx:alpine`), IDE TypeScript diagnostics (`StudentPortalPage.tsx` implicit `any` / `@tanstack/react-query` monorepo resolution), and missing fallback views—directing the upgrade to Active LTS `node:26-alpine` + `nginx:1.31.8-alpine-slim` (`21.8MB`), addition of `GlobalErrorBoundary`, `ErrorPage`, `NotFoundPage`, semantic `<progress>` loading states (`LoadingState` / `PageLoader`), elimination of all `any` types (`0` remaining), and `.vscode/settings.json` workspace `typescript.tsdk` configuration.
